# EOS-final-project
# Multiplayer Bomb Defusal System 💣

這是一個具有「資源爭奪機制」的多人拆彈遊戲。本專案將作業系統 (OS) 的核心概念（如多執行緒同步、互斥鎖、資源限制）融入遊戲機制中，讓玩家在拆除炸彈的過程中，真實體驗多個 Task 競爭有限資源的衝突與合作。

---

## 1. 遊戲規則

本遊戲由一位在 Raspberry Pi 前操作的「實體玩家」，以及多位透過網路連線的「線上玩家」共同參與。

* **勝利條件**：在 60 秒倒數時間內，成功剪斷唯一正確的解體線。
* **失敗條件 (BOOM)**：
  * 倒數時間歸零。
  * 剪錯線（剪到引爆線）。
  * **資源衝突 (Conflict)**：實體剪線是不可逆的事件，若實體玩家剪斷了一條已經被線上玩家「鎖定 (Lock)」的線路，系統會判定為非法存取並直接引爆炸彈。
* **操作限制與資源爭奪**：
  * **剪線鉗限制**：全場的虛擬剪線鉗數量有限（2把）。玩家必須先成功請求到剪線鉗，才能執行剪斷動作。
  * **線路鎖定**：每條線同一時間只能被一位玩家鎖定。
  * **提示配額**：每位玩家初始有 1 次提示配額，可向情報站獲取不重複的線索。若成功剪斷「安全線」（非正確也非引爆），可獲得額外的提示次數作為獎勵。

## 2. 程式功能與作業系統 (OS) 特性

本專案的核心由 `bomb_server.c` 與 `bomb_client.c` 構成，深度應用了以下嵌入式系統與作業系統特性：

### `bomb_server.c` (遊戲伺服器與資源管理器)
負責管理全域遊戲狀態、控制資源可用性、處理多玩家指令，並判斷實體與虛擬操作是否產生衝突。
* **Multi-threading (多執行緒)**：使用 `pthread` 實作 Connection-per-thread 模型。獨立的 Timer Thread 負責即時倒數計時，而 Client Handler Threads 則並行處理多個玩家的指令。
* **Mutex (互斥鎖)**：用於保護共享的 `GameState`（遊戲狀態、線路鎖、提示配額）。確保當多位玩家同時想鎖定同一條線時，只有先取得 Mutex 的任務能夠修改狀態，實現 Mutual Exclusion (互斥)。
* **Semaphore (信號量概念)**：用於管理有限數量的「剪線鉗」。當剪線鉗被借光時，後續的請求會被拒絕，展示了有限資源的管理與存取限制。
* **Blocking (阻塞與延遲)**：在處理 `HINT` 提示請求時，引入了 `sleep(3)` 來模擬系統處理高負載/解密資料的耗時操作。

### `bomb_client.c` (線上玩家終端機)
提供遠端玩家互動介面，發送指令並接收伺服器廣播。
* **Asynchronous I/O (非同步輸出入)**：實作了背景接收執行緒 `receive_messages`。利用 Mutex 保護終端機的「提示字串 (`active_prompt`)」，確保背景推播的倒數時間不會干擾玩家正在輸入的指令畫面，解決了 Console UI Tearing 的同步問題。

## 3. 團隊分工

本專案採模組化開發，以確保軟硬體整合的順暢與職責分離：

* **黃品岳**：負責軟體核心架構與網路通訊 (Server/Client)
  * **伺服器開發**：設計並實作 `bomb_server.c`，包含 Socket 連線池管理與 Timer 倒數狀態機。
  * **資源爭奪演算法**：實作 Resource Manager，利用 Mutex 保護線路鎖定，並以 Semaphore 控管剪線鉗的併發存取。
  * **配額系統實作**：開發不重複的動態提示生成演算法與配額獎勵機制。
  * **客戶端開發**：設計 `bomb_client.c` 終端機 UI，運用 Threading 解決非同步 I/O 造成的畫面撕裂問題。
  * **API 制定**：定義前後端對接的 ASCII 指令與廣播通訊協定。

* **藺弘瑞**：負責系統整合、實體客戶端開發與專案管理 (PM)
  * **硬體通訊橋接 (Physical Client)**：撰寫運行於樹莓派的自動化監聽程式。將硬體層偵測到的 GPIO 中斷事件，即時翻譯並封裝成 Socket 封包 (如 `CUT <wire_id>`) 發送至伺服器。
  * **壓力與衝突測試**：設計並執行整合測試 (Integration Test)，包含編寫腳本模擬多位玩家同時進行 `LOCK` 搶奪，驗證伺服器防禦 Race Condition 的穩定性。
  * **狀態機同步處理**：協調軟體 Server 與硬體 GPIO 的狀態，確保「遠端鎖定」與「實體剪線」衝突時，能正確觸發炸彈引爆。
  * **專案統籌**：繪製系統架構拓樸圖、狀態機流圖，並統整期末技術簡報。

* **藍國光**：負責硬體 I/O 與底層驅動 (Driver) 開發
  * **感測器驅動**：設計 GPIO 中斷處理邏輯，精準偵測 4 條實體線路的斷路事件，並提供 API 供整合端呼叫。
  * **硬體回饋系統**：透過 I2C/SPI 或 GPIO 實作七段顯示器 (即時同步倒數時間)、LED 狀態燈 (成功/失敗/鎖定) 以及蜂鳴器 (操作回饋與爆炸警報) 的控制模組。
  * **電路配置**：負責 Raspberry Pi 的實體電路佈線與硬體防彈跳 (Debouncing) 處理。

## 4. 對接程式與通訊協定 (API Specification)

為了讓硬體監聽程式（由藺同學開發）能順利與伺服器（由藍同學開發）整合，所有網路 Socket 通訊皆採用 ASCII 字串格式，並以 `\n` 作為指令結尾。

### 客戶端發送指令 (Client -> Server)
* `GET_CUTTER\n`：請求取得一把剪線鉗。
* `RELEASE_CUTTER\n`：歸還剪線鉗。
* `LOCK <wire_id>\n`：鎖定目標線路 (wire_id 範圍: `0` ~ `3`)。
* `CUT <wire_id>\n`：剪斷目標線路。**（注意：藺同學的硬體監聽程式在收到黃同學的 GPIO 斷路訊號後，必須透過 Socket 送出此指令）**
* `HINT\n`：請求消耗配額以獲取提示。

### 伺服器回傳格式 (Server -> Client)
* **廣播訊息 (Broadcast)**：
  * `TIME: <sec>\n` (每秒推播倒數時間，供七段顯示器更新)
  * `GAME_OVER: BOOM! ...\n` (炸彈引爆，觸發蜂鳴器長鳴)
  * `GAME_OVER: SUCCESS! ...\n` (拆彈成功，觸發勝利燈效)
* **操作回應 (ACK/REJECT)**：
  * **成功**：`LOCK_ACK: Success\n`, `CUTTER_ACK: Success\n`
  * **拒絕/失敗**：`REJECT: Wire already locked by others\n`, `REJECT: You must LOCK the wire first\n`, `CUTTER_REJECT: No cutters available\n`
